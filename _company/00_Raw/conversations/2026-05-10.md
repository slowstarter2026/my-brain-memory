통합 솔루션은 크게 **상품 관리**, **주문 처리**, **고객 관계** 세 가지 축으로 구성되어야 합니다.

| 영역 | MVP 기능 명칭 | 설명 | 우선순위 |
| :--- | :--- | :--- | :--- |
| **상품 관리 (Catalog)** | 상품 마스터 등록/수정 | 구매할 상품 정보(원가, 공급가, 예상 배송비)를 체계적으로 입력하고 관리. | 1 |
| | 재고 연동 기초 | 특정 상품의 현재 재고 수량을 표시하고 주문 시 차감하는 기초 로직 구현. | 2 |
| **주문 처리 (Order)** | 주문 생성 및 상태 관리 | 고객으로부터 주문을 받고, 주문 상태(결제 대기 $\rightarrow$ 배송 중 $\rightarrow$ 완료)를 시스템이 자동 업데이트. | 1 |
| | 주문 상세 내역 조회 | 고객별로 과거 주문 내역과 현재 진행 상황을 확인할 수 있는 기능. | 2 |
| **고객 관계 (CRM)** | 사용자 인증 및 관리 | 회원가입, 로그인, 개인 정보 관리를 위한 기본적인 보안 구조 확립. | 1 |
| | 주문/고객 연동 | 특정 고객에게 연결된 주문 목록과 구매 이력을 한눈에 파악. | 2 |

#### 2. 기능별 필수 학습 지식 (Claude/코딩 지식)

위 MVP 기능을 실제로 구현하기 위해 '바이브코딩' 과정에서 반드시 숙지하고 코드로 옮겨야 할 핵심 개념들입니다. 추상적인 이론보다 **실제 코드 구조**에 초점을 맞춰 학습하세요.

| MVP 기능 | 필수 학습 지식 (핵심 키워드) | 왜 필요한가? (목표) |
| :--- | :--- | :--- |
| **상품 마스터 등록/수정** | **데이터베이스 설계 (ERD)**, 관계형 데이터베이스(SQL), ORM 기초 (예: SQLAlchemy/Django ORM), JSON/YAML 파일 처리. | 상품 정보의 무결성을 보장하고, 데이터를 효율적으로 저장 및 조회하기 위함. |
| **재고 연동 기초** | **트랜잭션 관리**, 동시성 제어(Concurrency Control), 상태 머신(State Machine) 설계. | 주문 시 재고가 중복 차감되는 오류를 방지하고, 시스템의 일관성을 유지하기 위함. |
| **주문 생성 및 상태 관리** | **API 설계 (RESTful)**, HTTP 상태 코드 이해, 비동기 처리 (Async/Await), 데이터 유효성 검사(Validation) 로직. | 외부 연동(결제, 배송 API)을 위한 표준화된 인터페이스를 구축하고 오류를 최소화하기 위함. |
| **주문 상세 내역 조회** | **데이터 필터링 및 쿼리 최적화**, 인덱스(Index)의 이해, 효율적인 데이터 검색 알고리즘. | 대량의 주문 데이터에서 필요한 정보를 지연 없이 빠르게 추출하기 위함. |
| **사용자 인증 및 관리** | **비밀번호 해싱 (Hashing)**, 세션/토큰 기반 인증(JWT), 입력값 Sanitization (보안 취약점 방지). | 고객 정보와 시스템 접근 권한을 안전하게 보호하기 위함. |
